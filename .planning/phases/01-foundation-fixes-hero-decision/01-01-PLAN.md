<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| site → third-party profile (LinkedIn) | User leaves our origin via `target="_blank"`; the destination document gets a handle on our tab unless `rel` blocks it |
| site → public static asset (`/cv/*.pdf`) | An unauthenticated, uncredentialed file read served directly by the Cloudflare Workers static asset handler |
| site → search engines / AI answer engines (JSON-LD) | Structured data is a machine-readable identity assertion consumed by parties who cannot verify it independently |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | External social anchors in `src/components/Footer.tsx` and `src/routes/contato.tsx` | mitigate | Edit only the `url` string value; leave `target="_blank" rel="noopener noreferrer"` intact on every anchor. Dropping `rel` reintroduces reverse-tabnabbing (`window.opener` write access from the destination page). Asserted by the `rel="noopener noreferrer"` grep count in Task 2. |
| T-01-02 | Spoofing | `Person.sameAs` JSON-LD in `src/routes/index.tsx` | mitigate | `sameAs` is an ownership claim over an identity. Populate it only with `https://www.linkedin.com/in/murilo-ortega`, the URL the user explicitly confirmed in D-01 — never a guessed or inferred handle. An unverified `sameAs` asserts control over a profile that may belong to someone else. |
| T-01-03 | Information Disclosure | `public/cv/CV MURILO ORTEGA 2026.pdf` served publicly | accept | The CV is the intended deliverable of the primary recruiter CTA; public reachability is the requirement (FIX-01), not a leak. Contents are the same professional data Murilo publishes on LinkedIn. Note for the user: whatever personal contact details the PDF contains are world-readable and indexable — that is a content decision, out of this plan's scope. |
| T-01-04 | Denial of Service | Site availability during the fix | mitigate | All work lands on `feature/home-recruiter-redesign`, never `main` (Task 1). A push to `main` auto-deploys to the live site, so branching is the availability control, not a process nicety. Asserted by the branch check in Task 1. |
| T-01-SC | Tampering | npm/bun package installs (supply chain) | accept | This plan installs zero packages and runs no package manager. `package.json`, `bun.lock` and `package-lock.json` are untouched — assert with `git status --porcelain package.json bun.lock package-lock.json` returning empty. No `[ASSUMED]`/`[SUS]`/`[SLOP]` package surface exists, so no legitimacy checkpoint is required. |
</threat_model>
